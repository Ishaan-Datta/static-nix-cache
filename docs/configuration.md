# Configuration

`static-nix-cache publish` accepts the following options:

| Option | Environment | Default | Description |
|---|---|---|---|
| `--cache-dir` | | required | Local cache produced by `nix copy --to file://...` |
| `--output-dir` | | | Static metadata output directory |
| `--owner` | `GITHUB_OWNER` | repository context | Destination owner |
| `--repo` | `GITHUB_REPO` | repository context | Destination repository |
| `--token` | `GITHUB_TOKEN` | required | Token with `contents: write` access |
| `--release-tag` | `GITHUB_RELEASE_TAG` | `nix-cache` | NAR release tag |
| `--store-dir` | `STORE_DIR` | `/nix/store` | Store path advertised by `nix-cache-info` |
| `--priority` | `CACHE_PRIORITY` | `30` | Nix binary-cache priority |

Repository context falls back to `GITHUB_REPOSITORY=owner/repo` when owner and
repository are not supplied explicitly.

Compression is selected while creating the local cache:

```bash
nix copy --to 'file:///tmp/publish-cache?compression=zstd' /nix/store/...
```

Supported action values are `none`, `xz`, and `zstd`. The Rust publisher does
not recompress NARs; it preserves the bytes and metadata generated by Nix.
